# 文字识别（FlowOCR 整合）

文字识别是 Nonoka Sub X 字幕编辑器的**本地附加功能**，用于识别视频画面中的花字、标题、标注与游戏对话框，经用户配置的 LLM 翻译（或匹配游戏剧本）后自动追加为独立的 `ocr*` 轨道，支持按句定位、背景色底板遮盖，以及导出压制时用 LaMa 抹除画面原字。

---

## 1. 设计边界与平台支持

- **仅在本机运行，不上云**：上传整段视频违背 Nonoka 云端「只传音频」的隐私原则，因此文字识别与 LaMa 抹字全部在本地完成。
- **平台**：支持 **Windows**（推荐 NVIDIA 显卡 + 驱动 ≥ R580；无可用 GPU 时可退回 CPU，速度较慢）；macOS 暂不提供。
- **独立可选层 `screen-text`**：FlowOCR 使用 ONNX Runtime GPU 1.29 + CUDA 13.0 + cuDNN 9.13 + OpenCV 4.10，与主 `python` 层依赖冲突，因此打包成完全独立的可选层（含解释器、依赖与 PP-OCRv6 / LaMa 模型及预生成派生图，约 3–3.5 GB）。
- **唯一安装入口**：在主页面「**设置 → 运行环境**」的「文字识别层」一行下载、离线安装、修复或删除。编辑器内不提供安装入口。
- **沙箱与密钥隔离**：`engines/flowocr/` 以 `kind: "ocr"` 运行在密闭沙箱进程中，严禁注入任何 LLM API Key；翻译统一由核心经纠错包的 `llm.complete` 路由完成。适配器启动前绑定带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object，防止多进程残留。

## 2. 编辑器使用动线

1. **打开页签**：在字幕编辑器右侧栏切换到「**文字识别**」页签。
   - 若未安装 `screen-text` 层，页签会显示说明和「打开设置」按钮（点击跳回主窗口「设置 → 运行环境」）；层安装完成后页签自动变为可用。
2. **设置选项**：
   - **时间范围**：整片或自定义起止秒数。
   - **跳过主字幕带**：默认开启，避免重复识别画面底部语音字幕区。
   - **识别区域（ROI）**：点击「在画面上框选」后在左侧预览画面拖拽框定区域；可随时「恢复整帧」。
   - **翻译**：简体中文（使用用户已配置的 LLM，上下文自动附带 ±15s 默认轨语音字幕）或仅识别原文。
   - **遮盖方式**：纯色底板（取原字框四周背景色中位数）或不画底板（仍保留原字框供导出时 LaMa 抹除）。
   - **游戏剧本**：可导入 `gtd-bundle/1` 格式的 `.zip` 游戏剧本包（存入 `<数据目录>/engines/flowocr/gametext/`），识别到的台词直接匹配官方译文，未匹配的条目再交由 LLM 翻译。
3. **试 1 分钟**：点击「从当前位置试 1 分钟」仅识别播放头后 60 秒。结果以**临时叠加层**直接显示在预览画面里，不修改字幕文档，确认效果后可点「采用并全跑」或「丢弃」。
4. **后台运行与实时合并**：
   - 识别期间可继续编辑语音字幕并保存。
   - 任务结束后，服务端仅替换/追加 `ocr*` 轨道（默认轨、用户轨与云同步记录 `artifacts.json` 均不受影响；后续重跑语音转写亦会保留 `ocr*` 轨）。
   - 编辑器监听 `document:changed` 实时合并新轨道并自动补齐「文字识别」样式，支持 `Ctrl+Z` 撤销；若本地有未保存改动则自动 rebase 保留本地改动。即使漏收事件触发 409 保存冲突，只要服务端非 OCR 部分哈希一致，编辑器也会自动 rebase 并重试保存一次而不会锁死。
   - 已有 `ocr*` 轨被手动修改过时，重新识别会先询问「替换 / 保留为普通轨 / 取消」。

## 3. 按句定位、底板与导出

- **按句定位与底板**：每条文字识别句携带归一化坐标（`0..1`，与 `PlayRes` 无关）的 `pos` 与 `cover` 字段。在预览画面中可直接拖拽单句位置（自动吸附原字框边与中心），或在检查器中微调坐标、宽度、字号、对齐、底板颜色或「回到原位」。
- **SRT 导出**：默认跳过 `source.kind === "screen-text"` 轨道；需要时可在顶栏「导出」菜单勾选「SRT 包含文字识别」。
- **ASS 导出**：包含全部可见轨道（含 `\pos` 与底板绘图行）。
- **视频压制导出（LaMa 抹除）**：当文档含原字框且 `screen-text` 层就绪时，导出窗口显示「**画面原字：保留 / 抹除**」。
  - 选择「抹除」时，Go 端先检查临时目录磁盘剩余空间，发起 `screen-text-inpaint` 任务输出恒定帧率、保留色彩信息的无音轨中间成片 `cleaned.mp4`（NVENC `-cq 14` 或 x264 `-crf 12`），再以此为视频输入、原片为音频输入执行正常的最终编码与压制（不画色块底板，直接烧译文），完成后自动清理中间文件；取消导出会级联取消 LaMa 任务。
- **在面板里抹除原字并替换视频**：「文字识别」页签底部的「抹除原字」一栏可直接对整片跑 LaMa（`Service.EraseScreenText`），不必等到导出。
  - 抹字后的画面合回原片音轨（能复制就复制，MP4 装不下时转 AAC），存进视频缓存目录的 `erased/<媒体 ID>-<时间戳>.mp4`（每次抹除都用新文件名，避开播放器正打开的旧文件）；**原视频不会改动**。开工前会先确认缓存目录可写、磁盘空间够用。
  - `erased/` 不参与缓存容量淘汰，也不会被「清理视频缓存」删除（它就是条目的源文件，重做要几个小时），但计入缓存占用；迁移缓存目录时条目路径自动跟随。转写等任务直接读这份文件，不会再复制一份。
  - 完成后媒体库条目改为指向新文件，`Entry.erasedFrom` 记下原视频；字幕记录的指纹保持不变，云同步不受影响。编辑器打开着该视频时，前端先让播放器彻底松开旧文件（Windows 上被读着的文件换不掉），再调 `UseErasedVideo` 换源；旧的缓存副本与预览代理一并清掉。
  - 换成抹字视频后，预览和压制都不再画底板，导出窗口也不再提供「抹除」；重新文字识别仍读取原视频。面板可「重新抹除」（按当前原字框从原视频重抹）、「打开所在文件夹」或「换回原视频」（`RestoreOriginalVideo`，同时删掉缓存里的抹字文件）。重新抹除成功后、或从媒体库移除条目时，旧的抹字文件也会删掉。

## 4. 构建与维护

```bash
# 构建 screen-text 层（Windows）
python scripts/build_layers.py build --layer screen-text

# 校验层完整性与 FlowOCR 质量锁
python scripts/quality_gate.py --only layers --layers dist\layers
python -m pytest -q tests/test_flowocr_quality_lock.py tests/test_screen_text_package.py tests/test_screen_text_task.py
```

详见 [预制环境层构建手册](runtime-layers.md) 与 [Provider 接口规范](provider-spec.md) 第 14 节。
